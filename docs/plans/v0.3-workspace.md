# v0.3 Security Analytics Workspace

## Assessment and boundaries

Baseline: main at 9840364 (fetched 2026-10-30), clean working tree. Nx projects are web (SvelteKit 3/Svelte 5/Tailwind 4), api (FastAPI), api-client (generated OpenAPI types), and ids-core (existing Python engine). Existing shadcn Button, phosphor icons and JetBrains Mono require no new dependencies. Browser-local state remembers one analysis ID; the backend has bounded temporary sessions, no analysis-list endpoint or durable history.

Working features: CSV selection/drop, file limits, authoritative server schema validation/imputation, inference, summary, row/prediction/probability filters, sort/pagination, numeric flow detail, local SHAP waterfall/full table, sampled global SHAP, CSV prediction export, delete/expiry, saved evaluation/confusion matrix/provenance. Preserve all API and ML behavior.

UX problems: Dashboard appears active on every page; results lack a direct navigation entry; mobile navigation consumes page space; details require scrolling below the table; pale prediction colors fail on light backgrounds; duplicate CSS token blocks make dark styling inconsistent; technical metadata dominates the overview; no theme control; no distinction between file checks and server schema validation in the workflow.

## Design

Four primary areas: Overview (/), Analyses (/analyze), Traffic Explorer (/explorer plus /analyses/[id]), Model Insights (/model-insights). Explorer landing resolves the browser's current ID or explains how to import. No fabricated history. Overview prioritizes the current analysis and actual prediction distribution, with service/model information secondary. Retain existing route URLs and workflow action labels where useful.

Use a restrained blue/slate security workspace, readable system sans with monospace reserved for data. Single token source supplies light/dark surfaces, semantic benign/danger colors, keyboard focus, buttons, inputs, tables and notices. Follow OS theme initially and allow a persisted override. Responsive sidebar becomes a compact disclosure menu. Native nonmodal dialog acts as a right-side flow drawer so filters remain usable; Escape/close restores trigger focus. Explainability always describes model associations and class-1 probability, never causal attack evidence.

## Implementation plan and review boundaries

1. **Design foundations and shell**: consolidate layout.css tokens; refactor +layout.svelte navigation and responsive header; add theme helper/control and explorer landing. Test navigation and theme persistence.
2. **Overview and analysis**: prioritize current summary, add real class distribution and explicit empty/error states; make import/validate/detect/review progress honest about the single synchronous server request; show model feature requirements on demand. Preserve upload API and error text.
3. **Traffic Explorer**: add reusable drawer with Escape/focus behavior; preserve filters/page when inspecting; validate probability ranges; add clear filters and deletion confirmation; guard stale result requests; theme semantic badges.
4. **Explainability and Model Insights**: replace hardcoded colors; keep all signed/numeric values; progressively disclose technical contributions; expose uploaded-sample global SHAP from Model Insights with explicit dataset context, retaining existing explorer access.
5. **Quality and documentation**: browser coverage for desktop/mobile, themes, drawer, expiry, validation, navigation and regressions; screenshots; architecture/usage/design docs and validation record. No lint/formatter scripts exist at baseline; report this accurately rather than inventing gates.

Each boundary becomes a conventional commit and focused stacked PR when access permits. Run web check/test on each implementation boundary and full Nx check/test/build, contract drift and browser workflows at the end. Screenshots use only synthetic test fixtures. No deploy, release or auto-merge.
